# dsh-web-access

给 `dsh web` 加一个可以在设置页里改的固定启动令牌。

## 为什么需要它

`dsh web` 每次启动都会生成一个新的随机启动令牌，启动日志里打出来：

```
dsh web: http://127.0.0.1:3080/?token=<43 位随机串>
```

手机浏览器第一次访问时用这个令牌换一枚会话 Cookie，之后 30 天里靠 Cookie 访问。Cookie 一过期，手机就没凭据了，只能拿新令牌重新引导一次 —— 而令牌只在启动日志里，于是你得回到电脑前，重启服务，从日志里抄下那串 43 位字符，再手输到手机上。

如果这台电脑不在手边（比如塞在柜子里、用 frp 转发到公网给自己在手机上用），这一步就很烦。

这个插件把令牌固定下来：设置页里填一次，手机收藏一个网址。之后 Cookie 过期、dsh 重启、换手机，都只是点一下收藏夹。

## 设置页里的三项

| 字段 | 说明 |
| --- | --- |
| 手机访问地址 | 手机打开的地址，比如 `https://dsh.example.com/`。留空就用本机绑定地址 |
| 会话有效期（天） | `0` 表示沿用默认的 30 天 |
| 固定启动令牌 | 留空 = 每次启动随机；填了就固定下来 |

改完立即生效，不用重启 dsh。页面里还有当前手机网址的二维码，扫一下直接收藏。

令牌本身不会回传到浏览器：输入框始终是空的，只用占位文字告诉你「已经设置了固定令牌」，旁边有「清除固定令牌」按钮可以改回随机令牌。

## 安装

这个包是一个 dsh bundle，需要用插件管理装进你的 profile（设置 → 插件，或者让 agent 调 `plugin_manager install_bundle`）：

```bash
git clone <这个仓库> ~/dsh-web-access
cd ~/dsh-web-access
npm install          # 装 qrcode 依赖，装 bundle 时也会再执行一次
```

然后在 dsh 里把这个目录作为 bundle 安装进去。注意目录要放在**不会被系统清理的地方** —— 别放 `/tmp`，dsh web 是开机自启的服务，链接到 `/tmp` 的 bundle 会在重启后导入失败。

装好之后，设置 → 插件 → 点开「Web 访问」这个 bundle，描述和「包含的组件」之间就是配置表单。

## 已知限制

- 插件改的是 `@deepseek-ai/dsh-client-connection` 的两个内部字段（`browserAuth.launchToken` 和 `browserAuth.maxAgeMilliseconds`），它们不在 `connection` 服务的公开契约里。dsh 升级后可能失配 —— 插件会在启动时直接报错，而不是悄悄退回随机令牌让你以为还固定着。
- 固定令牌等于把这台机器的钥匙长期摊在公网上：拿到它就能换到完整的 agent 会话（跑命令、读写文件）。请用足够长的随机值、给 frp 套 TLS，最好在隧道层再加一层认证。
- 令牌交换只发生在站点根路径（`GET /`），所以「手机访问地址」不能带路径前缀，否则会 404/401。
- 手机地址必须能被 Host 的信任围栏放行，也就是 frp 转发的那个 authority 要在 `dsh web --trusted-host` 里。
